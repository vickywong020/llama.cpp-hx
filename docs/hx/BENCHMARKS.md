# 测试结果与限制

整理自 2026-09-23 至 2026-09-25 的本地测试记录。2026-09-29 源码发布及 README 补充核对了版本、文件哈希、文档和发布内容，没有重新运行模型或性能测试。历史 HX / legacy 对照与后续生产方案复测分开呈现。

## 历史 HX / legacy 对照

2026-09-23 r9 / H1 测试：同机比较 legacy 路径与 HX 8 线程，预留 262144 token、Q8_0 KV、物理批次 1024、加载 mmproj、parallel 1。2K 输入各测 3 轮、每轮解码 128 步，取中位数；32K 是单独长输入测量。单位为生成 token/s：

| 模型 / 实际输入 | legacy | HX 8 线程 | 相对提升（约） |
|---|---:|---:|---:|
| MXFP4 / 2K | 15.46 | 22.71 | 47% |
| Q5 / 2K | 13.97 | 18.78 | 34% |
| MXFP4 / 32K | 14.41 | 19.33 | 34% |
| Q5 / 32K | 12.45 | 16.11 | 29% |

数据核对了历史 `hx-20260923/hx-summary.json` 的 `mxfp4-legacy`、`mxfp4-hx8`、`q5-legacy`、`q5-hx8` 四个 case。相对提升为 `HX / legacy - 1` 的近似值。这里的 legacy 是当时本地 CPU 专家卸载路径，不是今天上游最新版本；不能将当前 Cache3G 的数值与这批 legacy 拼成新的加速比。

输出并非逐 token 完全相同。历史逐位置检查固定 13 个提示、每个 64 个位置，共 832 个位置；HX 与 legacy 的 top-1 一致率为 MXFP4 95.07%、Q5 91.47%。当时以 legacy 与 UEPT C=0 的一致率减 1 个百分点为阈值，MXFP4 通过；Q5 的阈值为 91.67%，HX 低约 0.20 个百分点，未通过原判据。后续报告讨论了舍入与判据改进，但本页不把讨论当作已通过验证，也不据此宣称质量等价。

来源：本地 `hx-20260923/HX-RESULTS.md`、`hx-20260923/hx-summary.json`。以下各节是 2026-09-25 的后续生产测量。

## 环境与方法

RX 9070 XT 16 GiB、Ryzen 7 9800X3D、192 GiB RAM，Windows；Qwen3.8-Flash-Next MXFP4 / Q8_0，加载视觉投影器。各方案预留 262144 token 容量；固定 WikiText 输入、129 token 输出。2K 输入重复 3 次，8K 输入重复 2 次；先以 512 输入 / 32 输出预热。

greedy、seed 42、`cache_prompt=false`、`ignore_eos=true`。串行运行一个模型，没有并行编译或压测；顺序为 MTP1、Cache3G、P2A。使用本机 `/completion` 流式 API，首字计到第一个非空文本块，含输入处理而不含启动加载。生成速度取服务端 timings。这是续写测试，不含聊天模板、思考、客户端渲染或多用户排队。

## 同轮比较

| 方案 | 实际输入 | 次数 | 首字秒 | 全部输出秒 | 输入 token/s | 生成 token/s |
|---|---:|---:|---:|---:|---:|---:|
| MTP1 | 2048 | 3 | 5.38 | 10.11 | 380.65 | 27.05 |
| Cache3G | 2048 | 3 | 7.57 | 12.09 | 271.29 | 28.36 |
| P2A | 2048 | 3 | 3.70 | 8.72 | 555.81 | 25.63 |
| MTP1 | 8192 | 2 | 20.95 | 25.79 | 391.29 | 26.46 |
| Cache3G | 8192 | 2 | 29.34 | 34.16 | 279.24 | 26.58 |
| P2A | 8192 | 2 | 14.23 | 19.38 | 576.39 | 24.87 |

各指标取重复中位数。P2A 是历史 `26394b4e67` 基线，不是当前 `main` 改几个参数的等价版本。

| 方案 | 专家缓存 MiB | GPU 路由专家 | 主 KV | 主批次 | MTP |
|---|---:|---:|---|---:|---|
| Cache3G | 3072 | 4 | Q4_0 | 256 | 关闭 |
| MTP1 | 0 | 0 | Q4_0 | 512 | 单草稿、GPU 驻留、草稿 Q4_0 KV / 批次 128 |
| P2A | 0 | 0 | Q8_0 | 1024 | 关闭 |

Cache3G 的 2K 生成比 MTP1 高约 4.8%，8K 高约 0.5%；尤其后者不支持稳定领先。MTP1 在另一些代码、工具格式文本更快。选择 Cache3G 是本地 decode 优先的取舍，不是对所有输入最快的声明。

各方案输出文本不完全相同，且同时改变多个变量，不能把速度差全部归因于 MTP、缓存或单个内核。未进行完整模型质量评估。

## 功能、长输入与显存

Cache3G 本轮通过中文计算、图表读数、鉴权、模型别名、流式结束、语法边界及嵌套工具参数检查。13 个固定提示与此前相同 Cache3G 配置的输出 token 一致 13/13；8 个批次边界和共享前缀回退重放通过。

- 实际 32768 token 输入：处理 273.15 token/s，生成 23.13 token/s，输出 65 token；随后短对话恢复正常。
- 短输入后进程专用显存约 13.47 GiB、整卡约 15.03 GiB；32K 后分别约 13.57 / 15.12 GiB。
- 显存为 Windows 快照而非峰值；共享内存包含主动固定在 CPU RAM 的专家，不能全部视为显存溢出。

MTP1 的独立生产验收使用 ubatch 512、主/草稿 Q4_0 KV、草稿 GPU 驻留，长输入结果如下。它与上面的 Cache3G 测量来自不同轮次，不能当作同轮速度排名：

| 实际输入 token | 输入处理 token/s | 生成 token/s | 输出 token | 进程专用显存 GiB | 整卡专用显存 GiB |
|---|---:|---:|---:|---:|---:|
| 32768 | 412.56 | 22.96 | 65 | 13.90 | 15.48 |
| 131072 | 343.96 | 15.86 | 65 | 14.02 | 15.60 |

长输入后短对话恢复通过。MTP1 与此前优化版的 13 个固定提示输出 token 一致 13/13，八个输入边界和前缀改写回放通过；这不能替代模型质量评估，也不能替代 Cache3G 的验收。本轮 Cache3G 只测到实际 32K，未测满 256K、长期稳定性或多用户并发。

生产启动器还负责硬件选择、鉴权和聊天模板适配。历史部署验证不等于自行编译后无需配置即可复现全部行为。复测应记录 commit、模型 revision / 哈希、SDK、驱动、硬件、KV、容量、实际输入长度、批次、采样和环境变量；先预热，再重复测量，同时检查功能和输出。
